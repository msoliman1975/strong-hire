# U13 · End-to-end, fidelity audit, cleanup

- **Branch:** `feat/ux-u13-e2e`
- **Waits for:** every other task.
- **Owns:** `apps/web/e2e/`, cross-cutting test updates, removal of dead v2 code that the new
  screens replaced.
- **Requirement IDs:** none new; verifies all of them.

## Goal

Prove the whole design works end to end and matches the mockups, then leave the code clean.

## Build

1. **Playwright journey** in mock mode with `v2_enabled` on, following the mockups' five flows:
   first use (profile → resume → reading → results → breakdown and issues → plan style → what
   first → Home); add a target role (three steps → role page); rehearse (interview page → take →
   live room → debrief → apply a suggestion → undo); build a story (Career Stories → craft → story;
   write it yourself → review → accept an edit); returning (Home plan item → interview, story,
   resume). Keep the v1 journey test passing.
2. **Fidelity audit:** run the fidelity check from `00-common.md` on every mockup route and every
   state the task prompts listed, at 1280 and 390. Fix what differs in this PR (small fixes) or log
   it in the PR as a follow-up when it belongs to a larger area.
3. **Brand pass:** the Strong Hire logo (never the mockup's square) and the lockup in the app
   and site, Strova's avatar identical to `reference/strova-avatar.html` in every place and mode,
   animations running and stopping under reduced motion, Strova's emails from "Strova from Strong
   Hire".
4. **Accessibility pass:** keyboard through each flow, focus visible, labels, contrast, reduced
   motion stops Strova's animation.
5. **Cleanup:** remove v2 components, routes and mocks that nothing uses any more (the old plan
   page parts, the old Home v2 sections, the old story library layout), keeping v1 and redirects.
   No requirement ID may lose its last test.
6. **Report** (the PR description): every requirement ID from `ux-spec.md` section 12 with its
   test, every mockup route with its fidelity result, the follow-ups, and all decisions logged
   during the build.

## Done when

The journey passes in CI, the full checks pass, and the report is complete.
